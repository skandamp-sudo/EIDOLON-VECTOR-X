A private snapshot also retains the original candidate, index, worktree diff and each numbered report. ## Where the bits first diverged

The 16D query was “telescope light”, relevant ID 6, Ocean target, Botanical protection, strength −1. Copies of identical binary64 values in contiguous arrays at eight different offsets modulo 64 produced distinct NumPy reduction results on this Accelerate-linked build. The numerator before unconstrained normalization stayed byte-identical. Its norm varied between 0x1.9169dd122476dp+0 and 0x1.9169dd122476ep+0. The governor first differed in the dot product of a protected basis row and the target (three coefficient patterns). Spherical steering first differed in projecting the query and signed target into that basis. Even holding endpoints fixed, the final cosine and protected drift could differ with address. Together these paths explain all six original fields. [First divergent operations](ascension-first.json) · [controlled alignment and 48 traced reports](ascension-trace16.json).

Both the encoded query and protected SVD basis stayed byte-identical during these controls. The requested thread limit was one. The observations establish address sensitivity in the installed numerical stack. Internal BLAS instructions and effective kernel thread counts were unobserved. The measurements here do not identify the cause of the earlier SciFact exchanges.

## Bounded correction

Only the ASCENSION comparison uses ordered binary64 products, math.fsum and square root for steering projections, normalization, gain, drift and cosine. Existing FOCUS geometry uses its original NumPy reductions. Rank policy, admissibility thresholds and the frozen experiments retain their definitions. The report identifies the reduction policy explicitly. The local research schema validates defaults so omitted and replayed thresholds serialize identically. Browser exports retain the original server JSON numeric tokens, including signed zero. The CLI checks canonical JSON for reports with the new policy.

## Verification

The [three-process gate](gate.json) checks 100 full negative-strength reports per process, three repeats for each of the other 11 model/strength cases, all 16 original decisions, the registered three-task fixture for each encoder, adjacent binary64 values on either side of the drift gate and all 13 frozen digests. All comparisons use exact report equality or exact hashes for replay. Historical comparisons check every ranking, retrieval metric, violation and gate separately. Coverage is limited to the tested fixtures and installed Intel Mac environment. These are engineering checks. Cross-platform replay and independent retrieval benefit remain unverified.

Run from the feature checkout with installed local assets and all three thread-limit variables in [environment.json](environment.json) set to 1. Run `.venv/bin/python scripts/verify_numerical_replay.py` followed by `node frontend/ascensionModels.mjs` with the loopback services running.
